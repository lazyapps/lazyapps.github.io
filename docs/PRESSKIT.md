# 产品 Press Kit

每个产品有 `/<product>/presskit/` 资料页，所有语言版本的产品页页脚链接到此页，并用 `#<BCP47>` 传递入口语言；首页页脚链接 `/presskit/#en` 汇总页。资料包覆盖该 App 实际支持的界面语言，法律等非产品页面不需要独立资料包。

产品页、资料页与汇总页使用共用的 `SiteHeader` 和 `LanguagePicker`。Press Kit 的选择器只切换 hash 和页面内容，不跳转路径；产品资料页右侧同时提供返回全部 Press Kits 的链接，汇总页只放语言选择器。资料页与汇总页使用主站共用的 `SiteFooterBase` 及其样式。汇总列表的图标用统一尺寸容器展示，保留原生透明边角，不用 CSS 二次裁切，下载素材保留原始文件。汇总页文案直接说明可下载的内容与选择入口，避免空泛宣传语。

所有带导航的页面（包括隐私页）共用 `SiteHeader`，产品页不另写导航背景或透明度规则。共用 header 在滚动位置为 0 时完全透明；滚动位置大于 0 时才启用覆盖整行的页面背景色 `var(--paper)`，背景不混合透明色、不降低不透明度、不使用 backdrop blur，回到 0 时立即恢复透明。始终不加底部边线，滚动后贴顶；前进后退恢复滚动位置时同步背景状态。FondFont 产品页通过 `SiteHeader` 的 `homeMark="sun"` 保留原版红色太阳、旋转与悬停效果及 `data-nav-sun` 光照锚点，减少动态效果时关闭动画。

全站页面用 `SiteGrain` 挂载磨砂纸纹，包括产品页、资料页、首页及隐私页。页面底色统一为 `var(--paper)`。纸纹与滚动后的 header 共用 `site.css` 中的纹理、尺寸、强度与滤镜；尺寸按全站 `--size-font` 缩放，不受某个页面正文字号影响。`SiteGrain` 的 `animated` 只控制已有纸纹动效，不另写纹理样式；系统开启减少动态效果时统一关闭纸纹动画。FondFont 保留静态纸纹、太阳与场景动画。

滚动后的 header 由 `SiteHeader` 自身提供纸纹，不依赖页面是否挂载全局纸纹。纸纹只叠加在不透明底色上，不让下方内容透出，也不改变游戏的纹理或层级；滚动位置为 0 时 header 的纸纹与底色都关闭。

层级遵循：嵌入游戏 1000、共用 header 1100、获焦跳转链接 1101、展开游戏 10000、预加载遮罩 10001。滚动时游戏不能遮挡导航；预加载遮罩必须覆盖导航，展开游戏的关闭按钮保持可用。

页面加载主站的 `src/assets/s/site.css`，复用字体、纸色背景、纹理、容器宽度、间距、圆角与 `--app-*` 产品配色。汇总页用同色产品卡片及胶囊按钮；产品资料页用相同的标题字体、按钮和图片容器。Hero 保持主站纸色背景，原版 App 图标不额外套彩色底壳、圆角或边框，保留清晰的正文对比和留白。不要另建一套 Press Kit 全局字体或颜色。

汇总页 hero 和产品列表也直接展示原版图标，尺寸容器不加彩色底框、内边距、阴影或额外圆角；保留原版图案与透明边角。

产品资料页按产品与整包下载、产品信息、按语言选择的文案与图片、使用说明与媒体联系组织。每次只展开一个语言的内容，提供对应 README.md；无 JavaScript 时各语言以可展开区块访问。页脚前区域由 `PressLayout` 自动接入共用的 `PressKitClosing`，汇总页与产品资料页的媒体联系布局保持一致；产品资料页额外折叠展示使用说明。

汇总页及所有产品资料页沿用主站预加载动画，主站首页与资料页共用 `SitePreloader`。汇总页显示 LAZYAPPS，产品页显示该 App 的英文品牌名；共用主站的文字揭示、进度条与退出时序，不加入额外宣传文案。动画结束后恢复页面纸色与 theme-color。入口语言照常通过 hash 初始化，切换语言不重播预加载；减少动态效果或无 JavaScript 时直接展示内容，动画依赖失败时最多 6 秒自动解除遮罩。

## 页面语言

Press Kit 保持现有路径，不创建语言子路径或自动重定向。所有资料页及汇总页共用 17 种页面语言，选择器沿用主站的语言原生名称与简写。优先读取 URL 的 `#<BCP47>`，其次是 `presskit.locale` 中保存的选择，再按浏览器语言匹配，最后使用英语；规范中文地区、语言大小写及地区标签。入口链接中的语言始终优先于偏好，不用 referrer 猜测。切换语言通过 JS 更新整页标题、功能摘要、按钮、产品信息、使用说明、媒体联系、页脚、document lang/dir 和选中的资料；浏览器前进后退同步恢复。中英不再并列展示。

汇总页卡片、返回全部资料链接、页脚的资料入口及各语言 README 中的资料页链接都携带当前语言 hash。返回产品网站使用真实存在的对应语言路径；KeyHop 意大利语资料返回其英语产品页。语言 hash 是页面状态，不使用相同的元素 ID，避免入站跳到资料区；`#main` 等普通内容锚点保留原有用途。

页面语言与资料包语言分别维护：`presskit-ui.json` 与 `presskit-presentation.mjs` 定义页面显示，`presskit-supported-languages.json` 与 `presskit-catalog.mjs` 定义 App 下载语言。网站有而 App 不支持的语言（如 KeyHop 的阿拉伯语、俄语、印地语）可以显示对应网站介绍，但只展示已有英语资料，并标明实际资料语言。World Book 与 XVDL 的资料仍只有英语；从其他语言的汇总页进入时保留页面界面语言，缺少的产品文案用英语并标明 lang/dir。不要为页面翻译虚构 App 支持语言、README 文件夹或截图。SEO 使用静态默认元数据即可，不建立语言 hreflang 组。

中英文并列产品名统一用间隔点，例如「爱装字体 · FondFont」「飞键 · KeyHop」「绎言 · YiYan」，简繁体保持同一规则。汇总卡片、产品资料页标题、资料文案和 README 共用名称来源；页面上的名称保持一行，窄屏适当缩小字号，不裁切或省略名称。

汇总页和各 App 资料页的标题末尾装饰点必须与前面的文字保持同行，所有页面语言遵循同一规则。汇总标题末行使用不可换行组合；App 标题通过 word joiner（U+2060）绑定末词与圆点，并使用正常单词换行，允许较长标题在前面的词间分行。不要用 `overflow-wrap:anywhere` 强行拆开这个组合；检查各语言及窄屏，防止孤立圆点和标题溢出。

## 图标来源与质量

必须从 App 原版资源生成图标，不使用旧 JPG、游戏精灵、只含符号的展示图或截图裁切。Icon Composer 工程使用 Apple ictool 导出 Default 1024 × 1024 PNG；已有 AppIcon PNG 直接使用原版最高分辨率文件。保留完整构图、比例与透明边角，不拉伸、补色或放大低分辨率素材。

原版资源快照与项目版本、文件哈希记录在 `scripts/assets/native-icons/sources.json`；已有原版 Icon Composer 工程可复用 `scripts/assets/<product>/AppIcon.icon`。更新图标时运行 `python3 scripts/export-native-app-icons.py`（需要 Xcode 内 Icon Composer），再生成资料包。网站构建验证来源快照、导出文件哈希和 1024px 尺寸，不依赖 Xcode 或私有项目。网页预览用 Astro 生成相应显示尺寸的 WebP，完整 PNG 作为下载文件保留。

## 资料包结构

ZIP 根目录直接放语言文件夹与共享素材，不套产品名文件夹。语言文件夹使用 App 的 BCP 47 标识，包含该语言的 `README.md` 和专属素材；可共享的图标、标志、图片只在根目录保存一份。README 用相对路径引用本地与共享文件。

```text
icon.png
settings-en.png
social-card.png
manifest.json
en/
  README.md
zh-Hans/
  README.md
  social-card.png
it/
  README.md
```

同一图片跨多个语言使用时按内容哈希去重，放到根目录。语言中立的图标和标志始终放根目录。共享截图保留真实界面语言并在说明中标明；对应语言的文件夹不能把共享英语截图说成该语言的截图。

## 新增产品

1. 从主 App 的本地化资源核对支持语言。在 `src/content/presskit-supported-languages.json` 记录语言、源文件与 App 提交版本；不把网站营销页语言或单独小组件语言当成 App 语言。更新 App 支持语言时同步此快照。网站构建使用已提交快照，不读取私有 App 项目。
2. 在 `src/content/presskits.json` 添加产品信息与基础素材；在 `src/content/presskit-catalog.mjs` 接入本地化文案和素材选择。复用现有产品翻译；App 语言尚无产品页翻译时补充对应媒体文案，不退回英语。各语言 README 的标题、介绍、状态、链接名称、图片说明与使用说明均使用对应语言；共用字段在 `src/content/presskit-glossary.json`。
3. 收录实际图标或透明标志、真实界面截图、已有 OG 宣传图。优先使用对应语言的截图与分享图，区别原生画面、标题画面和宣传图，保留原始尺寸与比例。独立于私有项目构建所需的截图放在 `scripts/assets/presskit/` 并记录来源。权限未明确的素材暂缓收录，给出明确说明和联系入口。
4. 运行 `python3 scripts/prepare-presskits.py`（Python 标准库和项目 Node 环境），提交生成的 `public/presskit/<product>/`。每个语言文件夹都有 `README.md`，文件内含官方链接、媒体联系、素材尺寸与来源说明；ZIP 根目录按上面的结构组织。页面提供完整 ZIP、所有语言 README 和逐张图片下载。网站构建不依赖 Python 或私有源项目。
5. 在产品页 `SiteFooterBase` 传入 `pressKit="/<product>/presskit/"` 及当前 `locale`，组件自动附加入口语言 hash。资料页和汇总页自动读取目录与共用页面语言；资料页不加入产品页的 hreflang 组。
6. 运行 `npm run build`，通过页面语言优先级、所有产品页入口 hash、App 语言覆盖、素材哈希与尺寸、共享文件去重、README 相对引用、ZIP 根目录结构、SEO 检查；检查桌面及窄屏、语言选择/前进后退/普通锚点与下载。

## 更新与产品发现

截图必须与当前 App 界面一致。更新对外素材时先核对 App 原版截图、当前构建或当前预览导出；界面改动后替换旧截图，不以文件修改时间或重新打包代替核对。优先保留原生全分辨率文件，保持原始像素、比例与实际界面语言。不要用旧版本地化截图覆盖新版界面；暂无新版对应语言截图时，使用明确标注真实语言的新版共享截图，语言文件夹与 README 仍覆盖 App 支持的语言。

在 `scripts/assets/presskit/screenshot-sources.json` 记录每张截图的来源、SHA-256、实际语言，以及每个 App 的核对日期和源码版本；已知的拍摄日期、构建版本一并记录，核对日期不冒充拍摄日期。原生截图和标题画面保持原样；经用户要求加工的展示图单独标注，并同时附上原始截图。构建必须验证目录中的全部截图都经过来源核对，来源快照哈希、网页下载文件和 ZIP 内图片完全一致。更换截图后同步资料说明，重新生成资料包，再通过完整构建；私有 App 项目只作为核对证据，不成为网站构建依赖。

产品页各语言的标题与正文直接说明功能、操作和适用平台，删去空泛宣传语。title、description、Open Graph 与应用结构化数据使用一致的产品定位。修改名称、功能、发布状态、下载入口或素材时，同步媒体目录及来源记录，重新生成资料包。测试版与即将推出的状态明确标注。

构建从页面 `SoftwareApplication` / `WebApplication` 数据独立识别产品，要求每个产品都有媒体目录及页脚入口。新增产品首页提供匹配自身 canonical 的应用结构化数据；工具、索引与法律页不作为产品。支持语言以 App 资源快照为准，而非网站页面数量。
