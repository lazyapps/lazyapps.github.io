# 国际化字体与 Hero 对齐检查 · 2026-10-20

## 范围与方法

- WebKit 手机 390px、桌面 1930px：83 个公开页面路径，共 166 次页面检查。
- Press Kit 汇总页与 7 个产品资料页：17 种界面语言、两种宽度，共 272 次语言状态检查。
- 使用构建后的静态页面，等待字体加载后检查文档横向溢出、可见标题宽度、内联节点行高和可见文本字形高度。字形测量使用实际字体、字号与大小写变换；隐藏辅助文字不参与测量。
- Hero h1 统一通过共享样式居中；语言切换后继续检查计算样式。

## 调整

| Before | After |
| --- | --- |
| 全局 `:lang()` 给标题内 span、br 直接赋正文行高 | 正文从 body 继承；标题内联节点继承标题行高 |
| 多种字体共用固定标题行高 | 使用 [字体与行高规则](../TYPOGRAPHY.md)，按字系及变音符号调整 |
| 嵌套 `lang` 继承外层字系的字体变量 | 显式语言边界先恢复默认值，再按语言设置字体 |
| Doze、FondFont、KeyHop、Press Kit 有独立固定行高 | 共享展示标题变量，保留字号及分行规则 |
| Hero 标题对齐不一致 | 全站 h1 居中 |
| 一饭图标高度仍按旧标题行盒计算 | 高度系数从 1.24em 同步为 1em |
| CHMate 印尼语、荷兰语的透明语言选择器产生窄屏溢出 | select 设置 overflow:hidden，保留 48px 点击区 |
| 土耳其文大写 İ 在部分标题中超出行高 | 土耳其文标题使用 1.14；Press Kit 汇总标题也遵循该值 |

## 结果与限制

检查结束时无文档横向溢出、标题宽度溢出或被测可见文本字形超过行高的记录。阿拉伯文及印地文保留所需变音符号空间，分别使用 1.36、1.42 的展示标题行高。

`npm run build`、`git diff --check` 通过。原始布局记录保存在本机 `/tmp/lazyapps-i18n-typography-audit.json`。本次检查针对当前 macOS WebKit 和已安装字体，其他操作系统的字体回退未覆盖。
