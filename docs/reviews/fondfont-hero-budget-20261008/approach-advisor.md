1. **Lossless WebP is appropriate.** Use `-lossless -exact`: lossless mode alone can change RGB values beneath fully transparent pixels. Verify decoded RGBA equality, preserve applicable color-profile metadata, and check browser rendering; identical channel values alone do not establish identical color management. 2. **Sparse and Meshopt savings are not additive in the installed toolchain.** glTF Transform 4.5.1 explicitly skips sparse accessors in its Meshopt encoder, while quantization clears the sparse flag on attributes it rewrites. Run sparse selection **after** quantization, then compare sparse storage against dense Meshopt storage. Dense zero-filled targets may compress better than sparse indices plus values. Preserve exact zeros; thresholding small deltas into zeros introduces another lossy operation. Three.js expands sparse data during loading, so do not claim corresponding runtime-memory savings.

3. **Do not use the default `meshopt()` wrapper for a position-only experiment.** It also reorders geometry and quantizes other attributes; its default high mode uses additional filters. Configure the underlying transforms explicitly, preserving UVs, normals, material identity, and morph names. Meshopt encoding itself can be lossless; its preprocessing need not be.
